The same shape elsewhere

  • Azure · ND H200 v5 (8 × H200) · ND GB200 v6 for 1M context — One 8-GPU deployment on AKS (NVIDIA device plugin, --tp 8) behind an internal ingress, or an Azure ML online endpoint; weights in Blob, fetched on boot; no public egress.
  • Azure, cheaper · NC A100 v4 × N — Ampere has no FP8: a quantized GLM-5.2 only, the same caveat as the local box.

Notes

  • Cost reality: this is a different tier. Eight H200s are about ten times the 31B box held warm, so the frontier class is scheduled for live load and scaled to zero between demos.
  • Per GPU-hour on Northflank: H100 $2.74 · RTX PRO 6000 96 GB $3.00 · H200 ~$3.14 · B200 ~$5.87.
  • Routing is unchanged: OpenClaw points at one endpoint; a LiteLLM or vLLM router in the same tenancy adds failover to a quantized fallback or a second region.

05Run it

# Launch ./llama-server -m GLM-5.2-UD-Q4_K_XL.gguf -ngl 99 -n-cpu-moe 999 -ts 50,50 -c 131072 --flash-attn --cache-type-k q8_0 --cache-type-v q8_0 --host 0.0.0.0 --port 8000 # Alternative ktransformers --model zai-org/GLM-5.2 --gguf_path ./GLM-5.2-UD-Q4 --cpu_infer 32 --max_new_tokens 131072 --port 8000
  • The engine keeps attention and KV on the cards and routes cold experts to RAM: llama.cpp (-ngl 99 -n-cpu-moe 999 -ts 50,50 --flash-attn --cache-type-k q8_0 --cache-type-v q8_0) or KTransformers for more expert throughput. OpenClaw points at the single OpenAI endpoint, exactly like the 31B box.
  • A 744B MoE owns all the memory: no room for image or voice on this box; run modality on a second machine as the standard build does.
  • Honest line: locally you run a quantized GLM-5.2 (4-bit is excellent); FP8 production parity is the 8-GPU node's job.
